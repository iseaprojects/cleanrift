# Architecture

## Projects

- `src/CleanRift` — WinForms application (`net9.0-windows`, x64).
- `tools/RenderForms` — diagnostic renderer for dialogs and icon sheets. It is
  not included in the portable package or installer.

## Layers

```
Program.cs            startup, elevation, single instance, job mode
Core/
  ProgramScanner      registry / MSI / Store discovery
  UninstallRunner     runs the program's uninstaller and waits for its tree
  LeftoverScanner     heuristic leftover scan
  RemovalEngine       deletes files, folders and registry items
  InstallTracker      real-time filesystem tracing + registry snapshot diff
  LiveFileMonitor     FileSystemWatcher/ReadDirectoryChangesW event collector
  TraceStore          trace XML read/write
  StartupScanner      Run/RunOnce, StartupApproved, scheduled tasks, Store
  StartupManager      enable/disable/delete/create startup entries
  AppSettings         preferences and local state
  UninstallCache      program/size cache
  Elevation*          relaunch and job execution
  JumpList            taskbar shortcuts
  HtmlExporter        self-contained HTML reports
UI/
  MainForm            list, explorer, menus, toolbar, status bar
  Theme               light/dark palette and control theming
  AppIcons            vector icon set
  Controls/           category strip, explorer, leftover tree, message dialogs
  Forms/              wizard, force removal, preferences, tracker, about, ...
```

## Startup flow

1. `Program.Main` handles `--job` first (elevated helper mode).
2. If the process is not elevated, CleanRift optionally starts the SkipUAC task;
   otherwise it relaunches itself with `runas` and exits.
3. The elevated process signals the SkipUAC launch event when applicable.
4. Single-instance mutex `Local\CleanRift` is acquired. A second process signals
   `Local\CleanRift_ACTIVATE`, waits for the first to close and takes over.
5. Settings and language are loaded, the theme is applied, the jump list is
   registered and `MainForm` starts the scan on `Shown`.

## Elevation and jobs

The UI runs as a single elevated process. For operations that need a second
elevation (for example when the first process could not be elevated), CleanRift
writes a JSON job to `%TEMP%\CleanRift`, launches itself with `runas --job`, and
waits for `<job>.result.json`.

Job kinds:

- `removal` — list of file/folder/registry items.
- `startup` — add, delete, enable or disable a startup entry.

## Data formats

- Settings: `%LOCALAPPDATA%\CleanRift\preferences.xml`, root
  `<CleanRiftPreferences version="1">`.
- State: `state.json`.
- Cache: `cache.dat`, magic `CLEANRIFT1\n` followed by JSON.
- Traces: `*_Traces.xml`, root `<CleanRiftTraces version="1">` with `Folders`,
  `Files`, `RegistryKeys` and `RegistryValues` sections.
- Languages: `Languages\English.xml` and `Languages\Spanish.xml`, generated from
  `languages/*.csv` by `tools/Build-Languages.ps1`.

## UI identity

- Accent color: teal (`#0F7B8A` light, `#5FD0DE` dark).
- Icons: generated by `AppIcons.cs`; the application icon is generated by
  `tools/Build-BrandAssets.ps1`. No third-party image assets are shipped.
- Dialog layout follows a compact task-pane style, not a pixel copy of any
  third-party product.

## Security notes

- The app elevates at startup because uninstallers and HKLM access require it.
- The optional SkipUAC task runs the current executable with `/tasksch` at
  highest available privileges. It is created only from Preferences and can be
  removed there.
- Removal jobs validate item kinds and registry paths in `RemovalEngine`.
- HTML output is HTML-encoded; trace XML is written with `XmlWriter`.
