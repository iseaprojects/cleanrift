# Audit — CleanRift 1.0 Beta 1

Date: 2026-10-30
Branch: `audit/fixes`

## Scope

Full pass over the core removal, elevation, scanning, tracing, startup and UI
code. The aim was to fix real defects and harden destructive operations without
changing the visible product design.

## Fixed

### Destructive operations and elevation

- Removal jobs are validated again in the elevated process: absolute local
  paths only, no UNC/device paths, wildcards, alternate data streams or
  reparse points.
- Protected locations are enforced in one place (`PathSafety`): Windows,
  System32, Program Files and its shared subfolders, ProgramData\Microsoft,
  user profile roots, shell folders and the application folder.
- 8.3 aliases (`PROGRA~1`) are expanded before protection checks.
- Registry removal refuses Windows hives, Run/Uninstall containers, Startup
  Approved containers and shared vendor umbrellas (`SOFTWARE\Google`, etc.).
  Removing a Run value remains allowed.
- Job files must live in the CleanRift job directory and cannot be reparse
  points. Elevation validates jobs before prompting for UAC.
- Missing registry keys/values now count as success instead of a failure.

### Command execution

- Removed shell lookup of `schtasks.exe` and `powershell.exe`; in-box tools are
  resolved from System32 so a file next to the portable app cannot hijack an
  elevated process.
- Registry links are restricted to HTTP/HTTPS; the Store protocol is handled
  separately.
- Store-app removal strips the registered quotes correctly and quotes the
  package name for PowerShell.
- Startup arguments are validated, and startup shortcut/task names are
  sanitized (reserved device names, trailing dots, length).
- Scheduled-task paths are now validated as task paths instead of being
  rejected for containing backslashes.

### Resources, cancellation and data

- Fixed process handle leaks in process-tree polling and install tracing.
- Fixed GDI leaks when rendering list icons.
- Fixed double icon-handle release in `ExtractIcon`.
- Scan cancellation is cooperative; a refresh requested during a scan now runs
  afterwards instead of being ignored.
- Settings, cache and trace XML are written atomically.
- Trace files now store their stable product id, and files include a short id
  hash so products with the same display name cannot overwrite each other.
- Display-name trace matching is only used when it is unambiguous.
- State files have size limits, so a damaged or hostile file cannot exhaust
  memory at startup.

### UI behavior

- Minimize-to-tray can no longer hide the window without a tray icon.
- The tray icon now reflects the preference from startup.
- A second instance now closes a minimized first instance correctly.
- Restoring a saved window position works across multi-monitor layouts.
- Force Removal / Removal Wizard no longer report “all traces removed” when
  some items failed, and pending-reboot items are reported explicitly.
- The Install Tracker now lets an in-flight tracking task unwind before the
  window closes.
- Localized the remaining partial-removal and reboot messages.
- Brand-neutral default export names.

## Verification

- `dotnet build CleanRift.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test`: 25 tests (path safety, command parsing, name matching, trace
  lookup, printf formatting, packed GUID conversion).
- Dialog/theme renders in English/dark and Spanish/dark.
- Elevated-job manual tests: normal file removal, protected file, 8.3 alias,
  vendor registry root, startup Run add/delete and scheduled-task validation.

## Residual risks (documented, not changed)

- The application always runs elevated. User-writable uninstall commands and
  SkipUAC tasks therefore inherit a high-integrity token. This follows the
  original product model; a future version should execute third-party
  uninstallers with a filtered token.
- Trace XML files live in a user-writable folder and are not signed.
- The build is unsigned; SmartScreen may warn.
- “CleanRift” has no trademark clearance.
